# ADR 003 · Encrypt the wardrobe with SQLCipher

Keep the rusqlite API and use `bundled-sqlcipher-vendored-openssl`. Phase 1's rusqlite 0.37 build option vendors SQLCipher 4.6.1 with a SQLite 3.46.1 core. Upgrade to rusqlite 0.43 for a newer SQLCipher source with later SQLite security fixes. On Windows the bundled C sources need a crypto provider. Vendoring OpenSSL statically removes the need for installed OpenSSL DLLs and keeps both packages on the same provider. Building requires MSVC, native Windows Perl and NMAKE. SQLCipher Community Edition carries BSD-style attribution requirements and OpenSSL carries its own license. Both notices ship in the packages. [SQLite security fixes](https://sqlite.org/cves.html)

Verify `cipher_version` and use a random derived 256-bit raw key before reading schema or enabling writes. Use a separate private database, full-page encryption and authentication, in-memory temporary storage, foreign keys and a DELETE rollback journal. Validate keys by reading schema, and use page authentication, SQLite integrity, and foreign-key checks during restore. The existing plaintext Phase 1 file contains a schema marker only. Preserve that file and carry its version into the encrypted storage metadata transaction. Reject unknown private schema versions and keep ordered migrations separate.

BitLocker depends on device configuration. Encrypting selected SQL fields would leave structure and some metadata exposed.
